Corrección de fechas de Cuenta corriente (2 de noviembre, pendiente confirmar recorrido real): el usuario reportó conversión `nvarchar` a `smalldatetime` en `/cc/1456`. El procedimiento suministrado recibe ambas fechas como `smalldatetime`, aplica límites inclusivos sobre `dbo.WEB_ConsultaCtaCte` y conserva parámetros tipados mediante `sp_executesql`, sin concatenar fechas. El usuario verificó en SSMS que `CONVERT(smalldatetime, '2026-12-30 23:59:59.999', 121)` devuelve `2026-12-31 00:00:00`, mientras que la alternativa sin segundos/fracciones devuelve `2026-12-30 23:59:00`: quitar precisión no sería equivalente. La evidencia apunta a la conversión implícita; no se inspeccionó la vista.

Se ajusta únicamente la llamada en `EducatioCommFunctions::CC_Obtener`: fecha formateada explícitamente `Y-m-d H:i:s.v`, enviada por binding a `CONVERT(smalldatetime, ?, 121)` y asignada a una variable local que recibe el procedimiento. Se usa `DECLARE` y `SET` separados, sin `TRY_CONVERT`, sin modificar idioma ni compatibilidad. Sintaxis apta para compatibilidad 100 y SQL Server 2014/2019; producción continúa sin verificar. Se conservan `FechaDesde = null`, ID del alumno parametrizado, cálculo `ultimoDiaMes()->addMonth()` y redondeo del servidor. No cambia el procedimiento ni datos. El helper es compartido por el controlador React y el controlador web legacy; conserva firma y resultado.
